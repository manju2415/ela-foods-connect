# Fix "stale" live site — PWA service worker update flow

## Diagnosis (confirmed, not guessed)
- The live deployment **is current**. The deployed JS bundle (`/assets/index-MBbxLce5.js`) contains the latest features — `founder-signup`, `referralCode`, `registration-payment`, `check-phone-registered` — and the live `index.html` matches the latest commit (`44c909c`). So publishing is NOT behind.
- The app is a **PWA** (`vite-plugin-pwa`, `registerType: "autoUpdate"`). The generated `sw.js` precaches `index.html` + the hashed bundle together and calls `self.skipWaiting()` + `clientsClaim()`.
- The staleness is **client-side caching** on returning visitors' devices: the old service worker serves the previously-precached old `index.html` (which references the old bundle) until a *new* service worker installs, activates, and the page reloads. The existing update prompt (`src/components/pwa/PWABadge.tsx`) attaches its `updatefound` listener **after** `navigator.serviceWorker.ready` resolves — a race that frequently misses the event, so the "New version available!" toast never shows and the user stays on the old version.
- The Supabase API runtime cache uses `NetworkFirst`, so backend data is not the culprit.

## What to change

### 1. Use vite-plugin-pwa's official update hook instead of the racy manual listener
Replace `src/components/pwa/PWABadge.tsx`'s hand-rolled `navigator.serviceWorker.ready` → `updatefound` logic with `useRegisterSW` from `virtual:pwa-register/react`. This hook is generated by the plugin and reliably fires `onNeedRefresh` when a new SW is waiting, eliminating the missed-event race. The visible UI (the "New version available! — Update" toast) stays the same; only the detection mechanism changes.

### 2. Make the update apply automatically
With `registerType: "autoUpdate"`, configure the `useRegisterSW` `onNeedRefresh` to auto-trigger the update (post `SKIP_WAITING` and reload) after a short delay, OR show the toast and reload on click. Recommendation: show the toast but also auto-apply after ~3s so returning users always land on the newest version without manual action.

### 3. Keep `skipWaiting` + `clientsClaim` explicit
The generated SW already calls these, so no `workbox` change is strictly required. (The bundle is correctly precached; an earlier inspection regex missed hashed entries that carry `revision: null`.)

## Immediate fix for your device right now
To see the current version immediately (before this code change ships): do a hard refresh (Ctrl/Cmd+Shift+R), or in DevTools → Application → Service Workers → "Unregister", then reload. On mobile, clear the site's stored data / cache for elabazar.com.
